Talk directly. No servers. No future computer reads it.

Lattice is an experimental framework for building peer-to-peer apps where your identity is a key on your own devices, messages flow straight between peers, and every exchange is sealed with a classical + post-quantum hybrid — secure even against the quantum computers that don't exist yet.

The idea

Built on what a server can't take away.

There's no account to breach, no inbox on someone else's machine, no central party to subpoena or shut down. The hard parts — identity, encrypted sessions, NAT-traversing connectivity, access control — are handled for you behind small, swappable interfaces.

No servers, by design

Peers find each other and connect directly (relay-assisted hole-punching), and your data lives on your devices. A company can't leak what it never holds.

Post-quantum from day one

Every primitive pairs a battle-tested classical algorithm with a NIST-standardized post-quantum one. Secure if either half holds — a hedge in both directions.

Forward secrecy that heals

A Double Ratchet rolls keys forward on every message and re-keys on every reply — so a stolen key can't unlock the past, and the session recovers after a compromise.

Your keys are your identity

An identity is a keypair you recover from a mnemonic — no signup, no password database. Stored in your OS keychain, or an encrypted file on headless hosts.

How it works

Clean layers, one swappable seam.

Each layer is a trait with a single job; dependencies point one way. The transport is the only place the network is named — in-memory today, iroh QUIC over relays and hole-punching for the real thing, anything behind the same interface tomorrow.

appyour application — e.g. the lattice-net chat
capssigned, offline-verifiable capability tokens — access by holding a key, not by a server's say-so
logappend-only BLAKE3 hash chain with a signature on every entry — tamper-evident, fails closed
sessionhybrid-KEM handshake + Double Ratchet — forward secrecy and post-compromise security
identitypost-quantum hybrid keypair, recoverable from a BIP39 mnemonic; device delegation
transport ←the swap seam — in-memory loopback & iroh QUIC (relay + hole-punch) behind one trait

An eavesdropper recording your traffic today, hoping to decrypt it once quantum computers arrive, gets nothing — the key is safe unless both X25519 and ML-KEM fall. Signatures work the same way: Ed25519 alongside ML-DSA, and both must verify.

Straight talk on security

What it protects — and what it doesn't, yet.

Trust comes from being specific. Here's the honest line between what's built and tested and what's still ahead.

Protected today

  • End-to-end message confidentiality & integrity
  • Post-quantum hybrid key exchange and signatures
  • Forward secrecy + post-compromise security (Double Ratchet)
  • No central server to breach, log, or compel
  • Memory-safe core — #![forbid(unsafe_code)] throughout
  • At-rest identity encryption (keychain / age)

Not yet (and we say so)

  • External security audit — none performed
  • Metadata privacy — who-talks-to-whom is not hidden
  • Strong Sybil resistance
  • Reliable redelivery of a message lost at the instant of a drop
  • A finalized name — "Lattice" is a working codename

Try it

Two machines, one ticket.

Lattice is a native app — there's nothing to run in this browser. Build the lattice-net CLI on two computers (or two terminals), and chat end-to-end encrypted over the real transport. You'll need Rust and outbound internet for the relays.

1

Build it

Clone the repo and build the chat binary on each machine.

# on each machine
git clone https://github.com/imcmurray/lattice
cd lattice
cargo build -p lattice-chat-example --bin lattice-net
2

Listen — and share the ticket

Device A starts listening and prints a ticket (its address + public identity).

./target/debug/lattice-net listen
# === TICKET (copy to the other device) ===
# c20df9fb228f…  (a long hex blob — copy all of it)
3

Connect and chat

Device B dials the ticket. Once both show "secure session established," type a line on either side — it appears, decrypted, on the other.

./target/debug/lattice-net connect c20df9fb228f…

Status

Where v0.1 stands.

Live-validated locally as a two-party encrypted chat with reconnect & resumption. The remaining frontier is a run across two physically separate networks, and the bigger features below.

Working now

  • PQ-hybrid identity with mnemonic recovery
  • BLAKE3 signed append-only log
  • Hybrid-KEM + Double-Ratchet session
  • Out-of-order & dropped-frame tolerance
  • iroh QUIC transport + the lattice-net CLI
  • Reconnect with session resumption

On the roadmap

  • Multi-writer rooms (CRDT-merged logs)
  • Metadata privacy (Tor / mix transport)
  • Reliable redelivery (acks + resend)
  • External security audit
